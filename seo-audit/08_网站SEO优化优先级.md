# 08 网站 SEO 优化优先级（P0–P3）

> 审计日期：2026-11-24 ｜ 本文件只列建议，**未执行任何修改**；所有条目需站长审核后再实施。
> 约束：实施时不得改动品牌资料、套餐价格、AFF 推广链接（含 `?code=` 参数）、既有 URL；对“重点保护页面”（见 01 报告第五节）的 Title 核心词与既有内链须保留。
> 声明：不承诺任何关键词进入 Bing 首页或前三；“可能影响”为基于技术与内容逻辑的预期，不是流量承诺。

## P0 影响抓取与索引的严重问题（上线前必须完成）

| # | 页面 / 文件 | 问题原因 | 修改方法 | 可能影响 |
|---:|---|---|---|---|
| P0-1 | `public/BingSiteAuth.xml` | 内容为占位符，Bing 站点验证无法通过，后续 sitemap 提交、IndexNow 反馈、搜索性能数据全部不可用 | 在 Bing Webmaster Tools 添加站点 → 选择 XML 文件验证 → 用真实 `<user>` 值替换占位符 → 重新构建部署；或改用 DNS CNAME 验证 | 解锁全部收录监控能力；是后续所有报告（09）数据来源的前提 |
| P0-2 | 域名 `jichang-jingxuan.blog` | 审计时 DNS 不解析，站点未上线；sitemap/IndexNow 中的 78 条 URL 与 `keyLocation` 均不可达 | 按 `docs/DEPLOYMENT.md` 完成 Cloudflare Pages 部署与自定义域名绑定，开启 Always Use HTTPS | 没有线上站点就没有收录；IndexNow 在 `keyLocation` 不可达时会拒绝请求 |
| P0-3 | 上线后状态码 | 未验证 http→https、无尾斜杠→有尾斜杠 301、404 状态 | 上线后逐项抓取确认（见 06 报告第四节清单）；如平台默认行为不符，添加 `public/_redirects` | 避免重复 URL 与软 404 被索引 |
| P0-4 | `src/pages/404.astro` | canonical 自动取 `Astro.url.href` 生成 `/404/`（不存在） | 为 404 页显式传入 `canonicalUrl` 或在 BaseLayout 中当 `noindex` 时不输出 canonical | 消除“canonical 指向不存在 URL”的技术信号（影响小但明确） |
| P0-5 | 上线后提交 | sitemap 未提交、IndexNow 未推送 | BWT 提交 sitemap；执行 `node scripts/indexnow.mjs --submit` 并记录响应码 | 加速首次发现 |

## P1 影响核心页面相关性、关键词定位与内容质量

| # | 页面 | 问题原因 | 修改方法 | 可能影响 |
|---:|---|---|---|---|
| P1-1 | 30 篇 `/articles/{slug}/`（源文件 `src/content/articles/*.md`，生成脚本 `scripts/generate-articles.mjs`） | 正文为同一模板，仅标题替换；相似度均值 0.77；标题问题未被回答 | 逐篇按标题重写正文（建议 1,200–2,000 字，含该标题专属的表格/步骤/数据，可引用 brands.json/plans.json 真实数据）；重写前可先只保留 6 篇首页精选文章对外索引，其余暂加 noindex 或从 sitemap 移除，避免模板内容先入索引；完成后统一移除 noindex 并重新推送 | 消除最大的重复/低质风险；让已覆盖的 17 个长尾标题真正具备可排名正文 |
| P1-2 | `/compare/` 与 `/plans/` | 正文相似度 0.929 | 方案 A：保留 /plans/ 为“套餐总指南”，/compare/ 改为只渲染筛选工具 + 精简表并 canonical 指向 /plans/；方案 B：/compare/ 改为“按品牌两两对比”差异化页面 | 集中“机场套餐价格对比”相关性到一个 URL |
| P1-3 | `/airports/` 与 `/ranking/` | 相似度 0.774，均为 18 张品牌卡 | /ranking/ 增加榜单评分维度表（线路/价格/客户端/稳定性各项评级）与每个名次的入选理由（300 字以上）；/airports/ 增加分类导览（按线路类型/价格区间/客户端政策分组）与横向对比表 | 让“机场排行榜”与“机场品牌大全”两个意图各有独立内容支撑 |
| P1-4 | 18 个品牌页 Description（`src/pages/airports/[slug].astro` 第 50 行 `metaDesc` 拼接逻辑） | 直接拼接 `lineType`/`regions` 字段，产生“。，”与内部核验备注，长度 128–181 字 | 改为每品牌人工撰写或从 `tagline/positioning` 生成 70–110 字通顺描述：品牌 + 线路类型 + 起步价 + 套餐数 + 主要用途；不改动品牌资料本身 | 直接影响品牌词结果页摘要与点击率；是全站最低成本高收益项 |
| P1-5 | `/`、`/recommend/`、`/articles/best-airports-2026-guide/` | 三页争夺“2026 机场推荐/优质机场” | 首页保持现状；/recommend/ Title 改向“机场怎么选/选购指南与核心指标”；文章 Title 改为更具体问句并从 /recommend/ 正文链接过去 | 主词权重集中到首页，方法论词集中到 /recommend/ |
| P1-6 | 8 组“专题页 vs 同名文章”（见 05 报告四-2） | Title 前缀几乎相同 | 规则：专题页 = “XX 机场推荐/选购”（列表 + 品牌卡），文章 = “XX 怎么判断/怎么做/原理”（方法）；修改文章 Title 与 H1 的措辞（保留 slug） | 消除内部竞争，形成“枢纽 → 深读”层级 |
| P1-7 | 8 个 `/plans/*/` 套餐专题页 | 独有正文 100–200 字，仅 1 个 H2；4 页仅 2 条入链 | 每页补 400–800 字选购说明（该价位能买到什么、典型用户、注意事项）+ 3–5 条 FAQ + 2–3 条指向相邻价位页与相关文章的链接；将 under-20/under-30/30-60/large-traffic 加入页脚“套餐与指南”栏 | 让 16 个商业转化词有实质承接页 |
| P1-8 | 首页、`/articles/`、`README.md` 中“30 篇原创深度文章”表述 | 与模板化事实不符 | 待 P1-1 完成后保留；若短期无法完成重写，先调整为中性表述 | 可信度一致性 |

## P2 长尾关键词与内部链接优化

| # | 页面 | 问题原因 | 修改方法 | 可能影响 |
|---:|---|---|---|---|
| P2-1 | 品牌页“相关机场品牌推荐”（`[slug].astro` 第 15–17 行） | 固定取前三名，入链集中于灵动云/暮光/微风（358/283/205），尾部品牌 60–70 | 改为按“同价位区间 + 相同线路类型 + 相邻排名”规则选 3 个；保留灵动云作为固定推荐位亦可 | 尾部品牌页获得更多相关入链 |
| P2-2 | 文章页“延伸阅读”（`[slug].astro` 第 114 行 `Math.random()`） | 随机选取，每次构建变化，链接关系不稳定 | 改为同分类优先 + 固定顺序；并在文章正文中加入 2–3 条指向对应专题页/套餐页的上下文链接 | 稳定的主题簇内链 |
| P2-3 | 全站锚文本 | “详情/查看详情/阅读全文/前往购买”为主 | 列表卡片保留按钮，但为标题元素增加带关键词的链接（如 `<a>灵动云机场怎么样</a>`） | 提升目标页关键词相关性 |
| P2-4 | 8 个场景专题页之间 | 无横向互链 | 每页底部增加“相关专题”模块（如稳定 ↔ 高端 ↔ 大流量；便宜 ↔ 20 元月付 ↔ 百元年付） | 专题簇权重流通 |
| P2-5 | 首页 FAQ 答案 | 无链接到对应深读文章 | 每条答案末尾加“延伸阅读”链接 | 文章入链 +8 |
| P2-6 | 品牌页 FAQ | 6 问为模板，无 FAQPage 结构化数据 | 为每品牌至少增加 2 条品牌特有问题（如灵动云“破晓/凌霄如何申请第三方订阅”）；输出 FAQPage JSON-LD | 问答型长尾承接 + 富结果机会 |
| P2-7 | 未覆盖/弱覆盖高意图词（机场哪个好、不限设备机场、全节点 1 倍率机场、原生 IP 机场、小火箭、油管、外贸机场） | 站内无 Title/H1 承接 | 按 07 报告建议页面在 H2 或 FAQ 中自然加入；不堆砌 | 扩展长尾入口 |
| P2-8 | `/value-airports/` | “每 GB 成本”概念有标题无数据 | 由 plans.json 构建时计算“每 GB 单价”表（价格 ÷ 月流量），按升序展示 | 独有数据型内容，难以被复制 |
| P2-9 | `/clash-airports/`、`/ai-airports/`、`/streaming-airports/` | 缺少 18 品牌支持矩阵 | 用 brands.json 的 `clientSupport.clash` / `streamingAi.*` 字段生成矩阵表 | 专题页独有内容量翻倍 |
| P2-10 | 文章页目录锚点（`[slug].astro` 第 84 行 id 生成） | 正则未去除“、”导致 href 与 id 不匹配 | 生成 id 时同时去除中文标点，或 TOC 使用与 id 相同的生成函数 | 修复页内导航（技术错误项） |

## P3 页面性能、用户体验及其他

| # | 页面 | 问题原因 | 修改方法 | 可能影响 |
|---:|---|---|---|---|
| P3-1 | 首页（243KB）、/plans/（180KB）、/compare/（176KB）、/plans/monthly/（109KB） | 完整渲染 142 行套餐表 + 18 卡片 | 首页只渲染精选 20–30 行并链接 /plans/；套餐页按筛选条件只渲染子集 | 降低首屏体积与抓取成本 |
| P3-2 | `/search/`（210KB） | 三份 JSON 内联 | 改为运行时 fetch `/search-index.json`（noindex 页，不影响收录） | 体积 |
| P3-3 | 30 张文章封面 JPG（2.0MB） | 无 WebP、无 srcset、无 width/height | 构建期用 sharp（已在依赖中）生成 WebP 与多尺寸；`<img>` 补 width/height | LCP/CLS |
| P3-4 | 全站 og:image | 0 页有；`dist/og/` 空 | 至少为首页/专题页/品牌页提供统一品牌图，文章页使用封面图；BlogPosting 补 `image` 与 `publisher` | 社交分享与富结果 |
| P3-5 | `src/pages/sitemap.xml.ts` | lastmod 硬编码 | 由数据文件/文章 `updatedDate` 实际值生成；品牌页用 `updatedAt` 真实值 | 更新信号真实 |
| P3-6 | `/ranking/` 名次显示 | 字符串拼接 `NO. 0{rank}` 产生“NO. 010” | 用 `padStart(2,'0')` | 体验/可信度 |
| P3-7 | 首页 H3 重复 | TOP3 品牌名在“本期精选”与“品牌网格”各出现一次 | 其一改为 `<div>`/`<p>` 或改用不同措辞 | 标题层级整洁 |
| P3-8 | 24 个超长 Title（最长 51 字） | 结果页截断 | 控制在 30 字左右，核心词前置 | 展示完整度 |
| P3-9 | `/contact/`（412 字）、`/about/` | 缺可验证联系方式与编辑信息 | 增加邮箱/表单与编辑介绍；Organization 补 `contactPoint`/`sameAs` | 可信度 |
| P3-10 | 托管安全头 | 无 `_headers` | 添加 HSTS、X-Content-Type-Options、Referrer-Policy | 安全/可信度 |
| P3-11 | 年份 2026（76 页） | 2027 年初将集中过期 | 建立年份变量，统一更新 | 时效维护 |

## 建议实施顺序

1. P0-1 → P0-2 → P0-3/P0-4 → P0-5（上线与验证）。
2. P1-4（品牌页 Description，半天内可完成）→ P1-2/P1-3（聚合页分工）→ P1-5/P1-6（Title 分工）→ P1-7（套餐页正文）→ P1-1（文章重写，工作量最大，可分批）。
3. P2 随 P1 同步在相应页面实施。
4. P3 在 BWT 有首批数据后，根据爬网统计与性能反馈排期。

> 实施任一项前，请先审核本报告；实施后建议重新运行本次审计脚本进行回归比对（标题/描述唯一性、相似度、入链分布）。
